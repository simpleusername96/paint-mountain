현황 결손 생성 조작 에셋 실행

Remediation report · 2026-08-02

기능은 있지만,
핵심 경험은 아직 아니다.

현재 프로젝트는 물리·페인트·세 기믹의 동작 기반은 갖췄습니다. 그러나 고정된 세 개의 완만한 산, 작은 primitive 아이템, 영어 전용 UI, 불분명한 조작 때문에 원본 지시문과 제공된 레퍼런스가 약속한 “거대한 산을 읽고 한 발을 계획하는 게임”으로 보이지 않습니다.

판정 · 시각 및 콘텐츠 기반 재작업 필요

기존 시스템을 버릴 필요는 없습니다. StageController, PaintSystem, 탄도/리플레이는 유지하고, 그 위의 지형 생성·배치·조작·현지화·HUD를 교체하는 것이 가장 안전합니다.

01 · Fresh running evidence

현재 실행 화면과 목표 사이의 거리

아래 “현재” 이미지는 이번 감사에서 Windows 릴리스 실행 파일로 새로 캡처했습니다. 레퍼런스와 생성 제안 이미지는 구현 증거가 아니라 비교·설계 기준입니다.

1

산을 먼저 읽게 한다

완만한 단일 봉우리 대신 층·능선·수로가 카메라에서 겹치지 않도록 생성하고 검증합니다.

2

아이템은 실루엣으로 보인다

텍스트 라벨에 의존하지 않고 원형·삼각형·방향성 형태와 화면상 최소 크기를 보장합니다.

3

UI는 산의 가장자리로 물러난다

상단 정보 3개와 하단 조작 3영역만 유지하고 산 위의 상시 패널을 금지합니다.

감사한 플레이 단계

1 · Briefing · 막힘

지형 확인: 산의 표면은 보이지만 경로와 기믹을 읽는 “브리핑” 목적을 충족하지 못합니다. 영어 설명도 기본 한국어 요구와 충돌합니다.

2 · Aiming · 막힘

한 발 계획: 탄도 기능은 있으나 조작이 화면에서 발견되지 않고, 기믹·탄착 마커·산의 구조적 깊이가 약해 의도적 조준이 어렵습니다.

3 · Paint flow · 부분 통과

결과 관찰: 파란 페인트와 범위는 보입니다. 다만 평면 마스크처럼 보여 “두껍고 만족스러운 흐름”이 약하고, 상단 보조 버튼이 시야를 분산합니다.

접근성 한계: 스크린샷으로 대비·크기·배치 위험은 확인했지만, 게임의 키보드 초점 순서, 스크린 리더 의미, 입력 반복 동작은 구현 단계에서 실제 조작 테스트가 필요합니다.

02 · Evidence-backed gap map

무엇이 있고, 무엇이 실제로 없는가

“없다”와 “있지만 사용자가 읽을 수 없다”를 구분했습니다. 우선순위는 현재 플레이 경험에 미치는 영향 기준입니다.

영역 현재 사실 필요한 상태 판정
산 생성 TerrainMeshFactory가 세 개의 고정 높이 수식 중 하나를 선택. RNG·seed·난도 지표 없음. 시드 기반 경로 우선 heightfield, 단계별 고저 반전·경로 폭·분기 지표, 제한된 재생성. P0 · 없음
아이템 배치 Stage Resource의 고정 X/Z 좌표를 그대로 spawn. 시야·경사·도달 가능성 검증 없음. 선반/능선/수로 후보 추출 후 기믹별 규칙, 화면상 최소 크기, LoS, 물리 경로 검증. P0 · 부분
기믹 동작 폭발·분열·범퍼의 효과, reset, payload, cooldown, 8-ball guard는 구현됨. 동작은 유지. 표현만 장면 기반의 두꺼운 3D 실루엣으로 교체. 유지
조준·파워 좌클릭 drag, A/D·W/S, wheel·Q/E, Space가 CannonController에 직접 결합. 마우스로 탄착 목표를 직접 지정, −/+·세그먼트·wheel로 파워 조정, Space/버튼 발사. P0 · 재설계
궤적 실제 탄도와 같은 계산으로 첫 충돌에서 중단. 기능은 맞지만 점·마커가 작음. 총구부터 첫 충돌까지 끊김 없이 표시하고, 탄착 링의 최소 화면 크기와 invalid 상태 보장. P1 · 개선
한국어 기본 en, 선택지도 en 하나. Translation resource와 tr() 사용 없음. 기본 ko, en 전환·저장, 전 화면 번역 키, StageData의 표시 문자열 분리. P0 · 없음
폰트·Theme Godot 기본 폰트와 각 노드의 크기/색 override. 공용 폰트·Theme 없음. Pretendard 기반 Theme, 일관된 weight/spacing/radius/focus, 한글 glyph 검증. P0 · 없음
외부 에셋 절차 primitive 외 runtime 에셋과 license ledger 없음. 승인된 CC0/OFL 파일만 최소 단위로 import하고 출처·버전·용도를 기록. P1 · 승인 필요
HUD layout 필수 영역은 있으나 고정 offset과 영어 텍스트, 약한 기믹/지형 위계. 레퍼런스의 edge layout, 한국어 fit, 1280/1600/1920 검증, 실제 아이콘. P0 · 재구성

03 · Deterministic procedural content

무작위 노이즈가 아니라, 경로를 먼저 만드는 산

산을 단순 noise로 만들면 게임이 아니라 우연한 울퉁불퉁함이 됩니다. 먼저 플레이 경로와 착지 선반을 만들고, 그 구조를 heightfield로 변환해야 합니다.

1 · Seed + Profilestage/version/seed와 난도 범위
2 · Route spines주 경로·안전 경로·착지 선반
3 · Heightfield능선·계곡·낮은 진폭 noise
4 · Metrics폭·경사·고저 반전·분기 검사
5 · Placement기믹별 후보·시야·하류 가치
6 · Layoutmesh/collision/paint/replay 공유

Stage 1 · 넓은 하강

  • 주 경로 1개
  • 고저 반전 0–1회
  • 경로 폭 24–32 m
  • 기믹 없음

Stage 2 · 분지와 선반

  • 경로 2개
  • 고저 반전 2–3회
  • 경로 폭 14–22 m
  • 상단 선반 폭발 노드 1개

Stage 3 · 다중 채널

  • 경로 3개 + 안전 저효율 경로
  • 고저 반전 4–6회
  • 경로 폭 8–16 m
  • 분열 + 범퍼

배치 알고리즘

  1. height grid에서 평탄 선반, 능선, 채널 입구, 하류 낙차를 추출합니다.
  2. 기믹 base 경사 18° 이하, 서로 10 m 이상, bounds 여유를 검사합니다.
  3. 조준 카메라에서 중심 LoS와 화면상 최소 지름(1920에서 32 px)을 확인합니다.
  4. 폭발은 높은 선반과 넓은 하류, 분열은 세 하강 섹터, 범퍼는 유효한 접근·출구 방향을 요구합니다.
  5. 실패 시 임의 좌표로 타협하지 않고 같은 seed sequence 안에서 terrain을 다시 생성합니다.

결정성과 실패 처리

  • stage_id + version + seed + profile이 같으면 grid checksum도 같습니다.
  • 최대 32회만 시도하고, 모두 실패하면 검증된 profile별 fallback seed를 사용합니다.
  • 재시작은 같은 layout을 사용합니다. 새 산은 새 레벨/명시된 seed에서만 생성합니다.
  • Replay에는 accepted seed와 profile version을 저장합니다.
  • PaintSystem은 동일 height grid로 downhill flow를 계산하며 두 번째 paint state를 만들지 않습니다.

04 · Aiming, power and trajectory

“각도를 조절”보다 “여기를 맞힌다”가 먼저다

현재 drag 감도는 플레이어의 의도를 화면에 드러내지 않습니다. 첫 탄착점을 직접 고르고, 파워가 만드는 포물선과 충돌 가능성을 즉시 보는 방식으로 바꿉니다.

확정된 입력 흐름

마우스를 산 위로 이동
hover 지점에 임시 탄착 링과 low-arc 미리보기를 표시합니다.

클릭 또는 drag로 목표 고정
현재 파워에서 가능한 yaw/elevation을 계산합니다.

− / + 또는 세그먼트로 파워 조절
클릭은 2%, hold는 300 ms 후 반복, wheel은 1% 단위입니다.

Space 또는 발사 버튼
valid 목표일 때만 한 발을 소비합니다.

궤적의 정보 경계

  • 총구부터 첫 실제 충돌점까지 모든 샘플을 연속 점선으로 표시합니다.
  • 마지막 구간과 탄착 링은 배경에 묻히지 않도록 outline과 최소 화면 크기를 가집니다.
  • 해가 없는 목표는 빨간 marker로 바뀌고 발사가 비활성화됩니다.
  • 파워가 바뀌면 같은 목표에 대한 각도와 궤적을 즉시 다시 풉니다.
  • 충돌 이후 bounce, 기믹 발동, 페인트 흐름, 최종 coverage는 보여주지 않습니다.
이 경계가 중요합니다. “끝까지”는 첫 탄착까지이며, 이후의 정답 경로까지 보여주면 원본 지시문의 퍼즐성이 사라집니다.

07 · Decision-complete execution

수정은 여섯 단계로 진행한다

상세 파일·소유권·검증 명령·실패 정책은 활성 ExecPlan에 기록했습니다. 아래 순서는 사용자에게 보이는 checkpoint를 앞쪽에 두고, 기존 물리 시스템 회귀를 매 단계 막습니다.

01

문서 계약과 회귀 기준

완료로 표시된 기존 문서를 실제 상태로 바로잡고, 생성 지표·한국어 용어·시각 비교 기준을 고정합니다.

02

하나의 생성 스테이지 완성

First Descent를 seed/profile 기반으로 생성해 기존 paint/state/replay 흐름까지 실제 플레이합니다.

03

난도 확장과 기믹 배치

Stage 2·3의 경로 복잡도, feature-aware placement, 화면상 크기와 전용 3D 실루엣을 완성합니다.

04

마우스 탄착 조준과 파워

입력 책임을 분리하고 direct target, −/+, invalid state, 첫 충돌까지의 선명한 preview를 구현합니다.

05

한국어 Theme와 승인 에셋

Pretendard, ko/en 번역, reference-aligned HUD, 선택한 CC0 파일과 license ledger를 적용합니다.

06

튜닝·릴리스·새 증거

세 physical solution, replay/save, 성능, 세 해상도, 두 locale, production export와 7개 실제 스크린샷을 검증합니다.

반드시 유지할 것

  • StageController의 상태·shot·clear/fail 단일 소유권
  • PaintSystem의 단일 runtime mask
  • 고정 60 Hz, CCD, 최대 8 ball, split 1세대
  • UI와 독립된 replay/agent command 경로
  • 첫 충돌 이후 정답을 보여주지 않는 planning puzzle

완료 증거

  • 같은 seed의 height grid checksum 일치
  • 세 단계의 route/reversal/width 지표 통과
  • 기믹 LoS·화면 크기·접근/하류 경로 통과
  • 새 save 한국어, en 전환·재실행 유지
  • release build의 새 7개 실제 화면과 60 FPS 평균
