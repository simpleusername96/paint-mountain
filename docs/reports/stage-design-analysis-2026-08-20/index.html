핵심 판단

01

Stage 01–06은 ‘도입’으로 읽힌다

Standard → Impact Burst → Apex Split을 순서대로 열고, 그 뒤 G+/R−와 R+/G−를 소개한다. 초반 여섯 단계는 기능 소개의 뼈대가 있다.

단, Stage 03은 route가 갑자기 3개로 늘고 Stage 04는 다시 1개로 줄면서 색상 규칙까지 바뀐다. 공간 난이도와 규칙 난이도가 매끄럽게 이어진다고 보기는 어렵다.

02

Stage 07–30은 5단계 규칙을 반복한다

R+G+ → G+R− → R+G− → G+R0 → R+G0가 계속 반복된다. 반면 목표 구간은 6단계마다, route는 Stage 08/18에서, 샷은 Stage 16에서, 시간은 Stage 11/21에서 바뀐다.

지형 진행의 staggered step 자체는 의도적이지만, 퍼즐 규칙의 5주기와 서로 다른 축들이 학습 단위로 결합됐다는 설계 근거는 없다.

03

10개 스테이지에서 한 색은 직접 점수 0이다

Stage 06과 10/15/20/25/30에서 Red는 0, Stage 11/16/21/26에서 Green은 0이다. 해당 색은 최신 writer로서 다른 색을 덮어쓸 수 있으므로 간접 영향은 있지만 직접 점수에는 들어가지 않는다.

이는 “빨강과 초록, 다양한 공을 사용해 목표 구간에 도달”한다는 의도와 긴장한다. 플레이어에게 별도 ‘지우개/덮어쓰기’ 역할로 명확히 가르치지 않으면 무의미한 공으로 보일 가능성이 높다.

04

공 종류 보장은 곧 전략 다양성이 아니다

Stage 07–30의 모든 deal은 Standard, Impact Burst, Apex Split을 포함하고 마지막 두 공을 반대 색 Standard로 고정한다. 구성 안정성은 높지만 지형과 mechanism에 따라 “왜 이 stage에서 이 공이 필요한지”는 달라지지 않는다.

공 종류를 허용하는 것, 실제 deal에 넣는 것, 그 공이 해법을 바꾸는 것은 서로 다른 수준의 증거다.

05

목표 구간은 도달 가능 분포가 아니라 공식으로 정해졌다

Stage 07–12는 7–11, 13–18은 8–12, 19–24는 9–13, 25–30은 10–14다. 지형은 커지고 mechanism은 3개에서 6개로 늘지만 밴드 폭은 항상 4다.

샷 수 증가와 특수 공 확산이 실제 점수 분포를 넓히는지, 좁히는지, 평균을 올리는지 측정하지 않았으므로 뒤 stage가 더 어렵다고 단정할 수 없다.

06

테스트는 정확하지만 질문이 다르다

480개 deal 검증은 길이, 종류, 색, correction reserve, 재현성을 확인한다. runtime smoke는 01–07/18/30에서 fire·paint·result 경로를 확인한다. 대표 late stage도 첫 공이 paint를 만들고 result를 내는지만 본다.

현재 테스트는 “망가지지 않았는가”에는 답하지만 “재미있는가, 풀 수 있는가, 여러 전략이 있는가”에는 답하지 않는다.

수정 순서

P0

Stage 07–30의 neutral 패턴을 재결정

두 색 모두 직접 점수에 기여해야 한다는 제품 의도를 우선하면 G+R0/R+G0를 제거하고 양수·감점 조합으로 재작성한다. neutral을 유지하려면 별도 ‘덮어쓰기 도구’로 명명하고 UI·튜토리얼·플레이테스트로 그 역할을 증명해야 한다. Stage 01–06 값은 source brief가 보존을 요구하므로 별도 승인 없이 바꾸지 않는다.

P0

점수 분포를 먼저 측정

각 stage의 고정 deal과 New Deal seed에서 실제 물리 실행으로 최종 R/G/score 분포를 수집한다. band는 단순 stage 번호 공식이 아니라 도달 분포, 의도한 실수 여유, 해법 다양성에 맞춰 다시 정한다.

P1

5개 챕터로 학습 목표를 명시

각 묶음에 ‘소개 → 연습 → 조합 → mastery’를 둔다. route 수, mechanism 종류, 색상 극성, 공 종류 중 한 번에 무엇을 새로 배우는지 StageData 옆 설계표에 명시한다.

P1

공 종류 요건을 stage-specific하게 조정

모든 late stage에 Burst와 Split을 강제하지 말고 지형·mechanism이 그 공의 공간적 장점을 실제로 요구하거나 보상할 때 넣는다. 마지막 두 Standard correction reserve는 안정성 장치로 유지할 수 있다.

P1

clear witness와 사람 증거를 분리해 축적

자동 witness는 적어도 하나의 clear 경로와 서로 다른 aim 전략을 확인하고, 플레이테스트는 실패 원인·재시도 수·규칙 오해를 기록한다. 둘 중 하나만으로 ‘밸런스 완료’를 주장하지 않는다.

P2

설계 문서의 scalar-coverage 잔재 정리

docs/design-spec.md 하단에는 여전히 unique coverage가 sole score라는 오래된 문장이 남아 있다. 상단 supersession과 source brief가 우선하지만, 다음 튜닝 전에 충돌 문구를 제거해야 한다.

근거와 적용 범위

로컬 근거

  • docs/source-brief.md — 모든 30개 stage의 signed Red/Green target-band와 세 공 종류, structural test의 한계를 규정한다.
  • src/stage_generation/stage_catalog_materializer.gd — Stage 01–06 authored 값과 Stage 07–30의 5-rule/6-band 공식을 소유한다.
  • src/stage_generation/stage_progression_data.gd — shot, time, route, mechanism, terrain 크기의 진행을 소유한다.
  • tests/all_stage_target_band_rule_test.gd, tests/target_band_stage_runtime_smoke_test.gd — 480 deal 구조와 대표 runtime 경로의 실제 검증 범위를 보여 준다.

외부 근거

  • MDA: A Formal Approach to Game Design and Game Research — mechanics가 만드는 dynamics는 상호작용 때문에 예측하기 어려우므로 구현 구조만으로 체험을 판단하지 않는 기준으로 사용했다.
  • Jenova Chen, Flow in Games — challenge와 player skill의 균형을 난이도 곡선 판단에 적용했다. 동적 난이도 조정 자체를 권고한 것은 아니다.
  • Microsoft Research, Automatic Game Progression Design — base concept뿐 아니라 배운 기술의 조합을 연습시키는 progression 관점을 chapter 재설계 권고에 적용했다. 이 연구의 자동 생성 방식을 그대로 도입하지 않는다.
  • W3C WCAG 2.2 · Use of Color — Red/Green 의미가 색만으로 전달되지 않도록 기호·형태·문자 단서를 함께 유지하는 기준으로 방향성 있게 적용했다.

한계

이 보고서는 코드·테스트·결정론적 실행 화면을 근거로 한 설계 감사다. 사람의 실제 플레이 세션, stage별 clear distribution, 접근성 사용자 테스트는 아직 없다. 따라서 점수는 현재 증거의 완성도를 평가하며, 재미를 측정한 결과가 아니다.
