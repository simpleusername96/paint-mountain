Executive verdict

기능은 들어갔지만, 정보가 하나의 경험으로 정리되지 않았다.

현재 UI는 작은 해상도에서도 대체로 잘리지 않고 필요한 기능을 제공한다. 그러나 점수, 목표 띠, 다음 공, 조준 값, 도움말이 서로 다른 카드처럼 흩어져 있다. 특히 브리핑의 큰 패널과 플레이 중 하단 전체 안내 막대가 산과 탄도를 가린다.

해결 방향: 기존 “Quiet Context” 디자인 언어를 유지하면서 모든 상태를 하나의 얇은 계기판 체계로 통합한다. 산은 항상 1순위, 다음 행동은 2순위, 설명은 요청할 때만 나타나게 한다.

2.4 현재 시각 정제도 / 5

가장 큰 문제

  • 화면 가장자리마다 다른 크기·밀도의 패널이 떠 있다.
  • 설명과 조작 정보가 플레이 공간보다 강하게 보인다.
  • 선택·활성·완료 상태의 시각 문법이 화면마다 다르다.

반드시 보존할 것

  • 산, 대포, 탄도, 페인트가 만드는 공간 중심 경험
  • 한국어 기본, 기존 조작과 기능, 데이터 진실성
  • 따뜻한 흰색·네이비·파란색의 승인된 테마

성공 기준

  • 3초 안에 현재 목표와 다음 행동을 읽는다.
  • UI가 산의 주요 실루엣과 착지 지점을 가리지 않는다.
  • 1–30 스테이지와 모든 상태가 같은 구성 규칙을 쓴다.

디자인 방향: Quiet Alpine Instrument

새 브랜드를 만드는 것이 아니다. 승인된 Quiet Context를 “산악 관측 장비”처럼 더 얇고, 연속적이고, 정밀하게 다듬는 방향이다.

World first. 화면 중앙은 산과 탄도에 돌려준다. 상태는 가장자리 레일에, 조작은 하단의 짧은 도크에, 설명은 접히는 한 줄 힌트에 둔다.

최신 화면에서 출발한 TO-BE

왼쪽은 저장된 최신 실행 캡처, 오른쪽은 같은 화면을 바탕으로 만든 목표 이미지다. 세계·카메라·핵심 기능은 유지하고 UI 구성만 바꿨다.

01 · 조준

흩어진 점수·목표·탄종·조작을 가장자리 레일과 하나의 조준 도크로 묶는다.

상태는 위로스테이지·공 수·진행 상태를 얇은 상단 바 하나로 통합한다.
목표는 왼쪽점수와 목표 띠를 세로 계기로 묶어 산을 덜 가린다.
행동은 아래로각도·파워·발사를 짧은 도크 한 줄에 배치한다.

02 · 스테이지 선택

카드 모자이크를 탐색 목록과 선택 상세의 안정적인 2열 구조로 바꾼다.

스캔 가능성완료·잠금·선택 상태를 같은 행 문법으로 비교한다.
선택 상세규칙·최고 점수·공 수는 선택한 스테이지에만 보인다.
명확한 시작파란색 주 행동은 화면당 “시작” 하나만 둔다.

03 · 브리핑

큰 설명 카드를 걷어내고 실제 산을 보면서 목표와 공 순서를 읽게 한다.

공간 먼저핵심 지형과 목표 지역을 가리지 않는 양쪽 계기 구성을 쓴다.
규칙 압축한 문장 목표와 수치만 남기고 긴 설명은 도움말로 옮긴다.
순서 시각화다음 공은 색·순번·특성의 동일한 작은 토큰으로 표시한다.

04 · 결과

세로로 긴 결과 카드를 좁히고, 점수 이유와 다음 행동을 한 흐름으로 만든다.

결과 이유총점 아래에 목표 띠와 실제 위치를 함께 보여준다.
행동 우선순위다음 스테이지를 파란색 주 행동으로, 재시도를 보조 행동으로 둔다.
세계 유지플레이 결과가 남은 산을 배경으로 충분히 보존한다.

전 화면·전 스테이지 적용 범위

테마는 스테이지별 복사본이 아니라 공유 컴포넌트로 적용한다. 1–6의 목표 띠 규칙과 7–30의 커버리지 규칙은 데이터만 다르고 동일한 시각 문법을 쓴다.

구현 시 지켜야 할 계약

한 화면, 한 파란 행동

발사·시작·다음 스테이지처럼 지금 해야 할 행동 하나만 파란색으로 강조한다. 선택 상태에는 윤곽선과 옅은 배경을 쓴다.

패널보다 레일

항상 보이는 수치는 화면 가장자리의 얇은 레일로 묶는다. 큰 중앙 패널은 일시정지와 설정처럼 세계 상호작용이 멈춘 상태에만 허용한다.

진실한 조건부 정보

목표 띠, 커버리지, 다음 공, 남은 공은 실제 게임 규칙과 StageController 상태만 표시한다. 장식용 가짜 값은 금지한다.

스테이지별 복제 금지

공유 테마와 공유 HUD 컴포넌트가 1–30을 소유한다. 스테이지 리소스는 값만 제공하고 레이아웃·색상을 소유하지 않는다.

반응형 우선순위

640×360에서는 설명→보조 레이블→장식 순으로 줄인다. 목표, 값, 발사, 뒤로 가기는 끝까지 남고 어떤 컨트롤도 잘리지 않아야 한다.

접근성

본문 대비 4.5:1, 큰 텍스트 3:1, 포커스 윤곽 2px 이상, 포인터 대상 44px 권장(최소 40px), 색만으로 상태를 전달하지 않는다.

중요: TO-BE 이미지는 구현 목표를 빠르게 합의하기 위한 합성 시안이다. 이미지 안의 작은 문구·수치·아이콘은 최종 데이터 계약이 아니다. 실제 구현은 현재 번역 문자열, StageController 상태, PaintSystem 결과, 승인된 에셋을 사용해야 한다.

근거와 방법

정적 문서만 보고 판단하지 않았다. 최신 실행 캡처, 구현 상태 기록, 디자인 권한 문서를 서로 대조했다.
